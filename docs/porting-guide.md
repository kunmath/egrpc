# Porting an upstream gRPC C++ client to egrpc

This guide covers moving an existing gRPC C++ **client** onto egrpc v0.1. The
short version: keep your `.proto` files and your generated-stub call sites,
make the proto graph lite-only, generate stubs with the pinned plugin, link
`libegrpc` instead of `libgrpc++`, and review the behavioral differences below.

The authoritative design is [egrpc-design-and-plan.md](egrpc-design-and-plan.md)
(§1 compatibility promise, §4.5 shim, §4.6 native API, §5.2 keepalive, §5.3
backoff, §5.8 `ClientReader` lifecycle).

## 1. Proto requirements

egrpc serializes through protobuf-lite (`MessageLite`) and never uses
reflection. Every `.proto` in the **transitive** import graph of your services
must build under the lite runtime:

```proto
syntax = "proto3";
package routeguide;
option optimize_for = LITE_RUNTIME;
```

The option is wire-neutral: Python, Go, Java and upstream C++ servers ignore it,
so the server can keep using the same files.

Not supported:

- protobuf reflection (`GetDescriptor()`, `GetReflection()`, `DescriptorPool`,
  `DynamicMessage`), text format and JSON conversion of messages;
- `google.protobuf.Any` reflection helpers (`PackFrom`/`UnpackTo` via
  descriptors) and any proto that only builds against full `libprotobuf`;
- server reflection and health-check services from `grpc++_reflection`.

## 2. Code generation

Message code (`.pb.{h,cc}`) and stub code (`.grpc.pb.{h,cc}`) come from two
different tools (see [codegen-pinning.md](codegen-pinning.md)):

- `.pb.{h,cc}` must be generated by a `protoc` that matches the **protobuf
  runtime you link against** (exact minor).
- `.grpc.pb.{h,cc}` must be generated by the **pinned `grpc_cpp_plugin`
  v1.85.4**.

### Desktop / CI

```sh
tools/pin-codegen.sh   # builds the pinned grpc_cpp_plugin v1.85.4 + protoc 35.1 into tools/bin/

# Message code: protoc matching the host runtime (protoc 21.12 for Ubuntu's
# libprotobuf-dev 3.21.12).
mkdir -p gen
protoc -I proto --cpp_out=gen proto/my_service.proto

# Stub code: pinned plugin.
tools/bin/protoc -I proto \
  --plugin=protoc-gen-grpc=tools/bin/grpc_cpp_plugin \
  --grpc_out=gen proto/my_service.proto
```

Use the default plugin options only. `services_namespace`, mock generation
(`generate_mock_code`) and other plugin options are outside the compatibility
envelope and unsupported.

### Yocto scarthgap

Codegen tools are host-side `-native` recipes and are never cross-compiled.
Use `protobuf-native` (protoc 25.8, matching the target protobuf 4.25.8
runtime) for messages and `egrpc-codegen-native` (installs
`egrpc-grpc_cpp_plugin`, pinned v1.85.4) for stubs. protoc 25.8 drives the
pinned plugin cleanly (verified empirically on v1.82.0; v1.85.4 emits
byte-identical stubs). From an application recipe:

```
DEPENDS += "egrpc protobuf protobuf-native egrpc-codegen-native"

do_configure:prepend() {
    install -d ${S}/gen
    ${STAGING_BINDIR_NATIVE}/protoc --proto_path=${S}/proto \
        --cpp_out=${S}/gen \
        --plugin=protoc-gen-grpc=${STAGING_BINDIR_NATIVE}/egrpc-grpc_cpp_plugin \
        --grpc_out=${S}/gen \
        ${S}/proto/my_service.proto
}
```

Never ship desktop-generated `.pb.{h,cc}` to the target. See
[meta-egrpc/README.md](../meta-egrpc/README.md) and
[yocto-spike.md](yocto-spike.md).

## 3. Build integration

Requirements: a C++17 compiler, nghttp2, OpenSSL and protobuf-lite.
`cmake --install` installs `libegrpc.so`, `libegrpc.a`, the `grpcpp/` and
`egrpc/` headers, and `egrpc.pc`. egrpc ships a pkg-config file (no CMake
package config), so in CMake use `find_package(PkgConfig)` plus
`pkg_check_modules`:

```cmake
cmake_minimum_required(VERSION 3.16)
project(my_client CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(PkgConfig REQUIRED)
pkg_check_modules(EGRPC REQUIRED IMPORTED_TARGET egrpc)
pkg_check_modules(PROTOBUF_LITE REQUIRED IMPORTED_TARGET protobuf-lite)

add_executable(my_client
  main.cc
  gen/my_service.pb.cc
  gen/my_service.grpc.pb.cc)
target_include_directories(my_client PRIVATE gen)
target_compile_options(my_client PRIVATE -Wall -Wextra -Werror)
# Generated code is not yours: exempt it from -Werror.
set_source_files_properties(gen/my_service.pb.cc gen/my_service.grpc.pb.cc
  PROPERTIES COMPILE_OPTIONS "-w")
target_link_libraries(my_client PRIVATE PkgConfig::EGRPC PkgConfig::PROTOBUF_LITE)
```

Without CMake: `g++ -std=c++17 ... $(pkg-config --cflags --libs egrpc protobuf-lite)`.
For static linking against `libegrpc.a`, use `pkg-config --static` so the
private `libnghttp2 openssl protobuf-lite` requirements are added.

Remove `grpc++`, `grpc`, `gpr`, Abseil, c-ares and re2 from your link line;
egrpc does not need them. (On scarthgap, protobuf-lite 4.25.8 itself pulls in
`abseil-cpp`; that is a protobuf dependency, not an egrpc one.)

## 4. Supported `grpc_cpp_plugin` version policy

- egrpc v0.1 supports stubs from **gRPC v1.85.4 `grpc_cpp_plugin`** only,
  default options, over a lite-compatible proto graph (design §1).
- `grpc::internal` is unstable upstream, so one plugin version is pinned per
  egrpc release. CI (`.github/workflows/codegen.yml`) rebuilds the pinned
  plugin, regenerates the checked-in stubs, diffs them against the checked-in
  copies and compiles them, so any drift fails the build.
- Supporting a future plugin version is done by **additive** shim changes;
  existing symbols are not removed or changed incompatibly.
- Outside the envelope (other plugin versions, `services_namespace`, mock
  generation, reflection-dependent protos) compatibility is not promised.

## 5. Behavioral and API differences from upstream gRPC C++

### TLS only

v0.1 is TLS-only (ALPN `h2`). `grpc::InsecureChannelCredentials()` compiles,
but `CreateChannel` returns a lame channel whose calls fail with
`UNIMPLEMENTED`. In-memory mTLS identity in `grpc::SslCredentialsOptions`
(`pem_private_key` / `pem_cert_chain`) also yields an `UNIMPLEMENTED` lame
channel; use `egrpc::ChannelConfig::client_cert_path` / `client_key_path`
instead. Targets accept `host`, `host:port`, `dns:///host:port` and
`[ipv6]:port` (default port 443); other schemes yield an `INVALID_ARGUMENT`
lame channel.

### Compile-present, runtime-`UNIMPLEMENTED`

Generated code for these compiles unchanged, but calls fail with
`UNIMPLEMENTED` (12) at runtime:

- client-streaming and bidirectional-streaming methods (`ClientWriter`,
  `ClientReaderWriter`);
- the async API (`grpc::CompletionQueue`, `PrepareAsync*`/`Async*` stubs):
  only `Finish` comes back with `ok = true`, after an `UNIMPLEMENTED` status
  is deposited; every other tagged operation (`Read`, `Write`,
  `ReadInitialMetadata`, `WritesDone`, …) comes back with `ok = false`;
- server-side generated classes (`Service`, `AsyncService`, …) exist only so
  generated files compile. egrpc has no server.

Unary calls and server-streaming `grpc::ClientReader` are fully supported.

### No compression

egrpc sends `grpc-accept-encoding: identity`. A server that still sends a
compressed message (flag = 1) fails the call with `INTERNAL`. Disable
response compression for egrpc clients on the server side.

### `ChannelArguments`

`grpc::CreateCustomChannel(target, creds, args)` honors these keys; every
other key is accepted and silently ignored:

| Key | Maps to | Notes |
|---|---|---|
| `GRPC_ARG_KEEPALIVE_TIME_MS` | `keepalive_time` | values `> 0` |
| `GRPC_ARG_KEEPALIVE_TIMEOUT_MS` | `keepalive_timeout` | values `> 0` |
| `GRPC_ARG_KEEPALIVE_PERMIT_WITHOUT_CALLS` | `keepalive_permit_without_calls` | `0` / non-zero |
| `GRPC_ARG_INITIAL_RECONNECT_BACKOFF_MS` | `initial_reconnect_backoff` | values `> 0` |
| `GRPC_ARG_MIN_RECONNECT_BACKOFF_MS` | `connect_timeout` | upstream's `MIN_CONNECT_TIMEOUT`, unified with `connect_timeout` (§5.3) |
| `GRPC_ARG_MAX_RECONNECT_BACKOFF_MS` | `max_reconnect_backoff` | values `> 0` |
| `GRPC_ARG_MAX_RECEIVE_MESSAGE_LENGTH` (`SetMaxReceiveMessageSize`) | `max_receive_message_size` | upstream's `-1` (unlimited) is ignored; the 4 MiB bound stays |
| `GRPC_ARG_MAX_SEND_MESSAGE_LENGTH` (`SetMaxSendMessageSize`) | `max_send_message_size` | values `> 0` |
| `GRPC_ARG_PRIMARY_USER_AGENT` (`SetUserAgentPrefix`) | `user_agent_prefix` | string |

Load-balancing, service-config, proxy, compression, retry and other upstream
keys have no effect.

### `ClientReader::Finish()` without draining

Upstream requires draining a server stream before `Finish()`. In egrpc,
calling `Finish()` before `Read()` returned `false` means "I'm done": it sends
`RST_STREAM(CANCEL)`, discards queued messages and returns the terminal
status (design §5.8). Destroying a reader without `Finish()` does the same
without blocking on the network.

### Keepalive defaults

- `keepalive_time` defaults to **300 s**, matching upstream servers' default
  minimum ping interval, so an unmodified server never sends GOAWAY for
  pinging.
- `keepalive_timeout` defaults to 20 s.
- `keepalive_permit_without_calls` defaults to **`true`** (upstream client
  default is `false`): dead links are detected even when no call is active.
- On `GOAWAY(ENHANCE_YOUR_CALM, "too_many_pings")` egrpc doubles
  `keepalive_time` for later connections and logs a warning.

### Reconnect backoff and GOAWAY

- Backoff uses gRPC's algorithm (1 s initial, ×1.6, 120 s max, ±20 % jitter)
  with `connect_timeout` (20 s) as `MIN_CONNECT_TIMEOUT`.
- Backoff resets only after a connection has stayed READY for
  `ready_stability_threshold` (default **60 s**), not on every successful
  connect. A crash-looping server is not hammered at the initial backoff.
- GOAWAY is **fail-and-replace** (one socket per channel): streams above
  `last_stream_id` fail immediately with `UNAVAILABLE` (known unprocessed,
  safe to retry); streams at or below it get up to `goaway_drain_timeout`
  (5 s) to finish, then fail with `UNAVAILABLE`. The connection is then
  replaced. Only retry non-idempotent unary calls on `UNAVAILABLE` if your
  application can tolerate duplicates.

## 6. Adopting the egrpc native APIs

Generated stubs work on any `std::shared_ptr<grpc::Channel>`, so these are
opt-in.

### `egrpc::ChannelConfig`

`#include <egrpc/channel_config.h>` exposes every channel knob with its
default. `egrpc::CreateChannel(target, config)` returns a channel usable with
unmodified stubs; an invalid config or target yields a lame channel failing
with `INVALID_ARGUMENT` (check up front with `Validate`).

```cpp
#include <egrpc/channel_config.h>

egrpc::ChannelConfig config = egrpc::ChannelConfig::CellularProfile();
config.ca_bundle_path = "/etc/myapp/ca.pem";
config.client_cert_path = "/etc/myapp/client.pem";  // optional mTLS
config.client_key_path = "/etc/myapp/client.key";
config.max_receive_message_size = 1024 * 1024;

std::string error;
if (!config.Validate(&error)) { /* report error */ }
std::shared_ptr<grpc::Channel> channel = egrpc::CreateChannel("api.example.com:443", config);
auto stub = routeguide::RouteGuide::NewStub(channel);
```

`CellularProfile()` sets `keepalive_time = 60 s`, `keepalive_timeout = 20 s`,
`keepalive_permit_without_calls = true`. **The server must allow it**: set
`GRPC_ARG_HTTP2_MIN_RECV_PING_INTERVAL_WITHOUT_DATA_MS <= 60000` and
`GRPC_ARG_KEEPALIVE_PERMIT_WITHOUT_CALLS = 1` on the upstream server.
Otherwise it answers with `GOAWAY(ENHANCE_YOUR_CALM, "too_many_pings")` and
egrpc doubles `keepalive_time`.

### `egrpc::resilient_stream<R>`

`#include <egrpc/resilient_stream.h>`. Wraps a server-streaming RPC and
re-establishes it on retryable failures (`UNAVAILABLE`, `RESOURCE_EXHAUSTED`,
`ABORTED`, `INTERNAL`, `UNKNOWN`, `DEADLINE_EXCEEDED`, and server-originated
`CANCELLED`; see `egrpc::DefaultShouldRetry`). The factory is called once per
attempt with a fresh `grpc::ClientContext` (wait-for-ready set); a deadline
set there applies to that attempt only. `on_reconnected` runs on the `Read()`
caller thread after a re-established stream receives initial metadata, never
on the EventThread. Use it to reconcile state missed while disconnected.

```cpp
#include <egrpc/resilient_stream.h>

int64_t cursor = 0;
egrpc::ResilientStreamOptions options;
options.on_reconnected = [&] { /* e.g. unary call to resync state */ };

egrpc::resilient_stream<routeguide::Feature> stream(
    options, [&](grpc::ClientContext& ctx) {
      routeguide::Rectangle rect = RequestFrom(cursor);  // resume from cursor
      return stub->ListFeatures(&ctx, rect);
    });

routeguide::Feature feature;
while (stream.Read(&feature)) { /* handle, advance cursor */ }
grpc::Status status = stream.status();  // terminal status
```

`stop()` is thread-safe and idempotent: it cancels the current attempt, wakes
any retry wait and makes `Read()` return `false` with `CANCELLED`. Do not call
`Read()` or `stop()` from inside the factory, `on_reconnected` or
`should_retry`. Retry delay knobs (`initial_retry_delay` 100 ms, ×1.6,
`max_retry_delay` 30 s, ±20 % jitter, `retry_reset_threshold` 60 s) live in
`ResilientStreamOptions`. A complete example is in
[examples/resilient_subscribe/main.cc](../examples/resilient_subscribe/main.cc).

### `egrpc::SetLogSink`

egrpc logs to stderr at `LogLevel::kWarn` and above by default. Redirect it
with `#include <egrpc/log.h>`:

```cpp
#include <egrpc/log.h>

egrpc::SetLogLevel(egrpc::LogLevel::kInfo);
egrpc::SetLogSink([](egrpc::LogLevel level, const char* component, const std::string& message) {
  my_syslog(egrpc::LogLevelName(level), component, message);
});
```

Sinks can be called from any thread, including a channel's EventThread, and
concurrently. They must be thread-safe, must not block and must not throw.
Passing an empty sink restores the stderr default.
