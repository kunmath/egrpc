# egrpc interop subset (M8)

egrpc ships an interop client, `egrpc_interop_client`, that runs the upstream
gRPC interop cases egrpc supports against a real upstream server. It uses:

- the upstream gRPC **v1.82.0** testing protos, copied verbatim into
  `tests/interop/proto/src/proto/grpc/testing/{empty,messages,test}.proto`. The
  only edit is `option optimize_for = LITE_RUNTIME;`, which changes nothing on
  the wire;
- `.pb.{h,cc}` generated by protoc 21.12, which matches the host
  `libprotobuf-dev 3.21.12`. `test.grpc.pb.{h,cc}` come **unmodified** from the
  pinned protoc 35.0 + `grpc_cpp_plugin` v1.82.0. Both sets are checked in under
  `tests/interop/gen/`, are excluded from clang-format, and are built with `-w`;
- an upstream `grpcio` server (`tests/server/interop_server.py`) whose
  `TestService` copies upstream
  `src/python/grpcio_tests/tests/interop/service.py` line for line.

## Running

```sh
cmake -S . -B build && cmake --build build -j
.venv/bin/pytest tests/test_interop.py -v                 # every case + CLI checks
.venv/bin/pytest tests/test_interop.py -v -k large_unary  # one case
EGRPC_BUILD_DIR=build-asan .venv/bin/pytest tests/test_interop.py -v
```

You can also run the client by hand against any TLS interop server:

```sh
build/tests/interop/egrpc_interop_client --server-host localhost \
    --server-port 50051 --ca-file cert.pem --test-case all
```

`--test-case` takes one of the cases below, `excluded_stubs`, or `all`. For
each case the client prints `INTEROP_CASE <name> PASS` or
`INTEROP_CASE <name> FAIL <reason>`. It exits with 0 when every case passes, 1
when a case fails, and 2 on a usage error.

## Supported cases

| Case | RPC(s) | Notes |
|---|---|---|
| `empty_unary` | `EmptyCall` | Same as upstream. |
| `large_unary` | `UnaryCall` | Same as upstream: 271828-byte request, 314159-byte `COMPRESSABLE` response. |
| `server_streaming` | `StreamingOutputCall` | Same as upstream: response sizes 31415, 9, 2653, 58979. |
| `status_code_and_message` | `UnaryCall` + `StreamingOutputCall` | Upstream uses `UnaryCall` + `FullDuplexCall`. egrpc has no bidi support, so `StreamingOutputCall` covers the streaming half. Both expect `UNKNOWN` / `"test status message"`. |
| `custom_metadata` | `UnaryCall` | Upstream also runs a `FullDuplexCall` leg. egrpc checks the unary leg only: the initial echo plus the 6-byte `-bin` trailing echo. |
| `timeout_on_sleeping_server` | `StreamingOutputCall` | Adapted. Upstream uses bidi `FullDuplexCall`. egrpc sends a `response_parameters` entry with `interval_us = 10 s` so the server sleeps, then expects `DEADLINE_EXCEEDED`. The `ClientContext` deadline is 100 ms; the acceptance bound is a looser `< 5000 ms` wall-clock elapsed time to tolerate slow CI hosts. |
| `cancel_after_begin` | `StreamingOutputCall` | Adapted. Upstream uses client-streaming `StreamingInputCall`. egrpc calls `TryCancel()` on a sleeping server-streaming call right after it starts, then expects `CANCELLED`. |
| `unimplemented_method` | `UnimplementedCall` | Same as upstream: expects `UNIMPLEMENTED`. |

The `excluded_stubs` case shows that the generated client-streaming
(`StreamingInputCall`) and bidi (`FullDuplexCall`) stubs compile against the
shim and return `UNIMPLEMENTED` (12) at runtime (design §2).

## Excluded upstream cases

| Category | Upstream cases | Why |
|---|---|---|
| Client streaming | `client_streaming` | Permanently out of scope (design §2). |
| Bidirectional streaming | `ping_pong`, `empty_stream`, `cancel_after_first_response`, `half_duplex` | Permanently out of scope (design §2). |
| Compression | `client_compressed_unary`, `client_compressed_streaming`, `server_compressed_unary`, `server_compressed_streaming` | egrpc only advertises `identity`. A compressed message fails the call with `INTERNAL`. |
| OAuth / GCP auth | `compute_engine_creds`, `jwt_token_creds`, `oauth2_auth_token`, `per_rpc_creds`, `google_default_credentials`, `compute_engine_channel_credentials` | Call credentials and Google auth are not supported. v0.1 is TLS-only. |
| Special / async / xDS | `cacheable_unary`, `channel_soak`, `rpc_soak`, `long_lived_channel`, `unimplemented_service`, `special_status_message`, `orca_per_rpc`, `orca_oob`, `pick_first_unary`, xDS / ALTS / load-balancer cases | These need GET/caching proxies, soak infrastructure, async APIs, ORCA, LB policies, or xDS, none of which are in scope. |
