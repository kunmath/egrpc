# egrpc

egrpc is a clean-room, **client-only** gRPC C++ library for embedded Linux
(Yocto). It is wire-compatible with unmodified upstream gRPC servers: code
generated by upstream `protoc` and `grpc_cpp_plugin` compiles and runs against
egrpc unchanged. Its only runtime dependencies are nghttp2, OpenSSL and
protobuf-lite: no Abseil, no c-ares, no vendored transport.

**Status: v0.1 complete (Milestones M0–M8).**

## Scope

| | |
|---|---|
| **Supported** | Unary calls with deadlines, server-streaming `ClientReader`, TLS with ALPN `h2` (optional mTLS), keepalive PING, reconnect with backoff and jitter, clean shutdown, `egrpc::resilient_stream`, `egrpc::ChannelConfig`, pluggable logging |
| **Compile-present, runtime `UNIMPLEMENTED`** | Client streaming, bidi streaming, async `CompletionQueue` API, server-side generated classes, insecure (plaintext) channels |
| **Permanently out of scope** | Server side, client/bidi streaming, xDS, interceptors, compression, c-ares, async completion queues |

## Footprint vs upstream gRPC C++

x86-64, Ubuntu 24.04, GCC 13.3.0, against upstream gRPC C++ 1.51.1. Full
methodology and caveats (the feature sets differ) are in
[docs/footprint-benchmark.md](docs/footprint-benchmark.md).

| Metric | egrpc | upstream gRPC C++ 1.51.1 | Ratio |
|---|---|---|---|
| gRPC library `.so`, stripped | 402,600 B (393.2 KiB) | 6,698,328 B (6.39 MiB) | **16.6x smaller** |
| gRPC library `.a`, `--strip-debug` | 723,872 B (706.9 KiB) | 23,336,044 B (22.25 MiB) | **32.2x smaller** |
| Full non-libc runtime `.so` closure of the shared client, stripped | 7,429,848 B (7.09 MiB) | 15,516,112 B (14.80 MiB) | **2.1x smaller** |
| ... same closure without the shared `libssl` + `libcrypto` (6,005,912 B) | 1,423,936 B (1.36 MiB) | 9,510,200 B (9.07 MiB) | **6.7x smaller** |
| Shared libraries in that closure | 5 | 51 | |
| `libabsl_*` libraries in that closure | 0 | 40 | |
| Client binary, gRPC library static + deps shared, stripped | 408,208 B (398.6 KiB) | 6,148,616 B (5.86 MiB) | **15.1x smaller** |
| Peak RSS (`VmHWM`), shared client | 10,556 KiB | 17,480 KiB | 1.7x smaller |

On Yocto scarthgap (aarch64), stripped `libegrpc.so.0.1.0` is 329,784 B and the
`libegrpc0` RPM is 148,309 B, with 0 `libabsl` entries in its DT_NEEDED.

## Quickstart

Dependencies (Debian/Ubuntu):

```sh
sudo apt-get install -y cmake g++ libnghttp2-dev libssl-dev libprotobuf-dev pkg-config python3-venv
```

Build and run the unit tests:

```sh
cmake -S . -B build && cmake --build build -j && ctest --test-dir build
```

Run the pytest integration and interop suites (they start upstream `grpcio`
servers and drive the built binaries):

```sh
python3 -m venv .venv
.venv/bin/pip install pytest h2 grpcio grpcio-tools
.venv/bin/pytest tests -v
```

Sanitizer builds (CI runs both; findings are blockers):

```sh
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=RelWithDebInfo -DEGRPC_SANITIZE=address,undefined
cmake --build build-asan -j && ctest --test-dir build-asan --output-on-failure
EGRPC_BUILD_DIR=build-asan .venv/bin/pytest tests -v

cmake -S . -B build-tsan -DCMAKE_BUILD_TYPE=RelWithDebInfo -DEGRPC_SANITIZE=thread
cmake --build build-tsan -j && ctest --test-dir build-tsan --output-on-failure
EGRPC_BUILD_DIR=build-tsan .venv/bin/pytest tests -v
```

Install (headers, `libegrpc.so`, `libegrpc.a`, `egrpc.pc`):

```sh
cmake --install build --prefix /usr/local
```

## Usage

### Upstream-compatible unary call

Existing client code keeps working; only the link line changes.

```cpp
#include <grpcpp/grpcpp.h>

#include "route_guide.grpc.pb.h"

int main() {
  grpc::SslCredentialsOptions ssl;
  // Empty pem_root_certs uses the system trust store; for a private CA, set
  // ssl.pem_root_certs to its PEM text.
  auto channel = grpc::CreateChannel("api.example.com:443", grpc::SslCredentials(ssl));
  auto stub = routeguide::RouteGuide::NewStub(channel);

  routeguide::Point point;
  point.set_latitude(409146138);
  point.set_longitude(-746188906);
  routeguide::Feature feature;

  grpc::ClientContext ctx;
  ctx.set_deadline(std::chrono::system_clock::now() + std::chrono::seconds(5));
  grpc::Status status = stub->GetFeature(&ctx, point, &feature);
  return status.ok() ? 0 : 1;
}
```

### `egrpc::ChannelConfig` + `egrpc::resilient_stream`

```cpp
#include <egrpc/channel_config.h>
#include <egrpc/resilient_stream.h>
#include <grpcpp/grpcpp.h>

#include "route_guide.grpc.pb.h"

void Subscribe() {
  egrpc::ChannelConfig config = egrpc::ChannelConfig::CellularProfile();
  config.ca_bundle_path = "/etc/myapp/ca.pem";
  auto channel = egrpc::CreateChannel("api.example.com:443", config);
  auto stub = routeguide::RouteGuide::NewStub(channel);

  egrpc::ResilientStreamOptions options;
  options.on_reconnected = [] { /* reconcile state missed while disconnected */ };

  egrpc::resilient_stream<routeguide::Feature> stream(
      options, [&](grpc::ClientContext& ctx) {
        routeguide::Rectangle area;  // build from your resume cursor
        return stub->ListFeatures(&ctx, area);
      });

  routeguide::Feature feature;
  while (stream.Read(&feature)) {
    // handle feature; call stream.stop() from another thread to end
  }
  grpc::Status final_status = stream.status();
}
```

`CellularProfile()` uses a 60 s keepalive; the server must allow it (see
[docs/porting-guide.md](docs/porting-guide.md#egrpcchannelconfig)). A full
example is in [examples/resilient_subscribe](examples/resilient_subscribe/README.md).

## Supported `grpc_cpp_plugin` version

`grpc::internal` is unstable upstream, so each egrpc release pins one code
generator. **v0.1 supports stubs from gRPC v1.85.4 `grpc_cpp_plugin`** (default
options, lite-compatible protos), built by `tools/pin-codegen.sh` together with
protoc 35.1. CI regenerates the checked-in stubs and fails on drift. Message
code (`.pb.{h,cc}`) must come from a `protoc` matching your protobuf runtime.
See [docs/codegen-pinning.md](docs/codegen-pinning.md) and
[docs/porting-guide.md](docs/porting-guide.md).

## Upstream interop

All **8 of 8** applicable upstream interop cases pass against an unmodified
upstream `grpcio` `TestService`: `empty_unary`, `large_unary`,
`server_streaming`, `status_code_and_message`, `custom_metadata`,
`timeout_on_sleeping_server`, `cancel_after_begin` and `unimplemented_method`.
Cases needing client/bidi streaming, compression, OAuth or xDS are excluded.
Details and adaptations: [docs/interop.md](docs/interop.md).

## Yocto scarthgap

[meta-egrpc](meta-egrpc/README.md) is a Yocto layer for **scarthgap (5.0 LTS)
only**:

- `egrpc` (`egrpc_git.bb`): the target library (`libegrpc0`, `libegrpc-dev`,
  `libegrpc-staticdev`), fetched from `https://github.com/kunmath/egrpc`.
- `egrpc-codegen-native`: host-only pinned plugin, installed as
  `egrpc-grpc_cpp_plugin`; pair it with `protobuf-native`'s protoc 25.8.
- An example `core-image-minimal.bbappend` to copy into your own layer.

`libegrpc.so` has zero Abseil linkage, but scarthgap's protobuf-lite 4.25.8
depends on `abseil-cpp`, so images with generated protobuf stubs ship it too.
See [meta-egrpc/README.md](meta-egrpc/README.md) and
[docs/yocto-spike.md](docs/yocto-spike.md).
